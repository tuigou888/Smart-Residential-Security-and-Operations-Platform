# 智慧安防小区运营平台 — 演示系统就绪性评估

> 评估日期：2026-10-20  
> 评估范围：后端 API (端口 8088) + 前端 SPA (Vite) + MySQL 数据库 (48 张表) + Redis 缓存  
> 评估目的：判断当前系统是否可作为演示系统向客户/领导展示，识别差距与补救建议

---

## 1. 总体结论

| 维度 | 状态 | 评分 |
|------|------|------|
| **后端接口可用性** | ✅ 全部 63 个核心接口通过冒烟测试 | ⭐⭐⭐⭐⭐ |
| **前端页面完整性** | ✅ 40 条菜单均有落点 (15 专用 + 25 通用) | ⭐⭐⭐⭐ |
| **数据类型完备性** | 🟡 有初始数据，但部分模块为空 | ⭐⭐⭐ |
| **设备联动真实度** | ❌ 流媒体/云台/远程开门均为演示降级 | ⭐⭐ |
| **待办模块缺失度** | ❌ 巡更/AI/报修/黑名单等完全未实现 | ⭐ |
| **演示就绪综合评分** | **🟡 可作为基础演示，关键亮点需提前说明** | **⭐⭐⭐** |

**一句话结论**：  
系统已具备**基础 CRUD + 告警工单闭环 + 数据统计大屏**的演示能力，但**设备联动/流媒体等核心 IoT 特性为演示降级**。若演示目标是"展示平台架构与业务流程"则充分；若目标是"现场演示设备远程控制"则不充分。

## 3. 演示降级/缺陷清单 (需提前说明)

### 3.1 流媒体与视频监控 ⚠️ **核心缺陷**
| 功能 | 现状 | 演示替代方案 |
|------|------|--------------|
| 实时预览 (`/video/live`) | `srs.media.enabled=false` 时返回演示地址 | 展示流地址字段，说明真实环境对接 ZLMediaKit |
| 云台控制 (`/video/ptz/control`) | 仅写日志，返回 null | 点击后展示"已触发云台控制"日志 |
| 视频截图 (`/video/snapshot`) | `url=null` | 展示请求链路，说明需要摄像头硬件 |
| 录像回放 (`/video/playback`) | 返回演示地址 | 同实时预览 |

**影响**：无法在现场演示"真正的视频监控"，需准备 PPT/录屏补充。

### 3.2 设备联动 ⚠️ **桩接口**
| 接口 | 实际效果 | 预期效果 |
|------|----------|----------|
| `/iot/device/restart` | 仅写状态日志 | 下发重启指令到设备 |
| `/access/remote-open` | 仅写通行记录 | 远程开门 |
| `/vehicle/gate/open` | 仅写通行记录 | 道闸抬杆 |
| `/base/owner/face-upload` | 仅写字段 | 对接人脸库 |

**影响**：IoT 相关交互只能"点到为止"，需强调"流程打通，设备层待对接"。

### 3.3 前端只读限制 ⚠️ **体验割裂**
| 模块 | 后端能力 | 前端状态 | 演示规避策略 |
|------|----------|----------|--------------|
| 用户/角色/菜单/部门 | CRUD 齐全 | 只读列表 | 用 admin 账号直接改数据库演示 |
| 楼栋/单元/房屋/业主 | CRUD 齐全 | 只读列表 | 前期准备数据，演示中不做增删 |
| 告警规则 | CRUD 齐全 | 只读列表 | 同上 |
| 通道/录像计划 | CRUD 齐全 | 只读列表 | 同上 |

**原因**：`frontend/src/config/modules.ts` 中 25 个 CRUD 模块仅有 3 个配置了 `createApi/updateApi/removeApi`。

**修复工作量**：每个只读模块约 10-20 行配置调整，预计 2-3 人时可补齐。

## 5. 缺陷与风险摘要

### 5.1 必须修复 (P0)
| 缺陷 | 影响 | 修复工作量 |
|------|------|------------|
| 工单 `close()` action 误写为 `"upgrade"` | 状态流转错误 | 1h 修复 + 回归 |
| `countOwners(communityId)` 忽略参数 | 数据统计不准确 | 1h 修复 |
| 房屋导入未解析楼栋/单元名 | 数据关联易丢失 | 2h 修复 |
| 单号生成用 `Math.random()` | 高并发冲突风险 | 2h 改雪花算法 |

### 5.2 安全加固 (生产前必须)
| 问题 | 建议 |
|------|------|
| DB 密码明文在 `application.yml` | 改用环境变量或 KMS |
| AES 密钥硬编码 | 外置密钥管理服务 |
| CORS `allowedOriginPatterns=*` + `allowCredentials=true` | 收紧白名单 |
| `/file/*` 接口仅要求登录 | 加 `@PreAuthorize` |
| 登出 Token 不失效 | Token 黑名单或短 TTL |

### 5.3 工程优化
- 前端无代码分割，chunk 大于 500KB
- 无单元测试，依赖冒烟脚本验证
- 演示账号硬编码在登录页
