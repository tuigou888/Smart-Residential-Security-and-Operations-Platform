# 文档一：《智慧安防小区运营平台总体建设方案》

## 1. 项目背景

随着新型智慧城市与智慧社区建设推进，住宅小区安防正从"单点技防"向"平台化、智能化、运营化"升级。当前小区普遍存在：

- 视频、门禁、车行、消防等系统**各自为政**，形成信息孤岛；
- 安防以**事后查证**为主，缺乏事前预警、事中联动；
- 物业人力成本上升，安保效率低、事件闭环难；
- 人脸、住户、车辆等数据采集使用**缺乏合规管控**。

建设统一的智慧安防小区运营平台，是提升小区安全水平、物业运营效率与业主满意度的必然选择。

## 2. 建设目标

**总体目标**：建成"一平台统管、一张网统联、一块屏统览、一终端统服"的智慧安防小区运营体系。

**具体目标**：

| 目标维度   | 指标描述                                          |
| ---------- | ------------------------------------------------- |
| 设备全接入 | 视频、门禁、车行、消防、电梯等设备统一接入率≥95% |
| 事件全闭环 | 告警自动派发、处置、反馈、归档闭环率≥98%         |
| 预警智能化 | 重点场景AI识别覆盖率100%，告警秒级推送            |
| 运营可视化 | 运营大屏实时呈现安全态势与运营指标                |
| 服务在线化 | 业主开门、访客、报修等高频服务100%线上化          |
| 安全合规化 | 满足等保2.0、个人信息保护相关要求                 |

## 3. 建设原则

- **统筹规划、分步实施**：统一架构，分期建设，先核心后扩展；
- **标准先行、利旧兼容**：优先GB/T 28181、ONVIF、MQTT等标准协议，兼容存量设备；
- **云边协同、平战结合**：中心平台做运营，边缘节点做接入与实时联动，断网可自治；
- **安全可控、合规运营**：数据加密、权限管控、全程审计、授权采集；
- **开放扩展、持续演进**：微服务架构、标准接口，支持后续扩展与多小区复制。

## 4. 总体架构

采用"五层+三体系"架构：

```text
┌──────────────────────────────────────────────┐
│ 展示层：物业Web端 安保App 业主小程序 运营大屏 监管端 │
├──────────────────────────────────────────────┤
│ 应用层：安防管理 设备管理 事件工单 巡更 消防 车辆     │
│         访客 业主服务 统计分析 多小区运营            │
├──────────────────────────────────────────────┤
│ 平台层：IoT中台 视频中台 AI中台 数据中台            │
│         消息中心 规则引擎 工作流 统一认证 文件服务     │
├──────────────────────────────────────────────┤
│ 边缘层：边缘网关 AI盒子 NVR 门禁控制器 协议转换      │
├──────────────────────────────────────────────┤
│ 感知层：摄像头 门禁 车牌机 烟感 电梯传感器 报警设备    │
└──────────────────────────────────────────────┘
 侧翼体系：标准规范体系 | 安全保障体系 | 运维管理体系
```

## 5. 重点建设内容

1. **统一安防中心**：视频、门禁、车辆、访客、报警、消防、电梯、周界统一管理；
2. **AI智能预警**：周界入侵、消防通道占用、电动车进电梯、人员徘徊、高空抛物等；
3. **事件闭环处置**：规则引擎+工单引擎，告警自动派单、限时处置、复核归档；
4. **设备全生命周期管理**：台账、状态、告警、维保、升级；
5. **业主服务入口**：小程序开门、访客邀请、报修、缴费、通知；
6. **运营决策支撑**：安全指数、设备健康度、工单效率、通行分析、领导驾驶舱；
7. **多小区集中运营**：集团-项目-小区三级管控，支持规模化复制。

## 6. 安全保障体系

- **物理/网络安全**：边界防火墙、WAF、HTTPS、MQTT TLS、专网/VPN；
- **数据安全**：敏感字段加密存储、脱敏展示、视频访问鉴权、下载审批、备份恢复；
- **应用安全**：统一认证、RBAC+数据权限、接口鉴权、防重放、审计日志；
- **合规管理**：人脸等敏感信息授权采集、最小化采集、保存周期策略，满足《个人信息保护法》《数据安全法》、等保2.0（建议二级，涉及重要数据按三级建设）。

## 7. 建设阶段

| 阶段 | 周期    | 内容                                   |
| ---- | ------- | -------------------------------------- |
| 一期 | 3~5个月 | 基础平台+视频/门禁/车辆/访客/告警+大屏 |
| 二期 | 3~6个月 | AI分析+规则联动+工单闭环+消息中心      |
| 三期 | 3~5个月 | 业主小程序+缴费报修+多小区运营+报表    |
| 四期 | 持续    | 数据智能+数字孪生+社区治理对接         |

## 8. 投资估算框架

| 类别     | 主要内容                                                      |
| -------- | ------------------------------------------------------------- |
| 软件平台 | 平台开发/授权、AI算法授权、地图/短信/云服务                   |
| 前端硬件 | 摄像头、门禁、车牌机、道闸、传感器、AI盒子、NVR、服务器、大屏 |
| 工程实施 | 勘测、布线、安装、联调、培训                                  |
| 运维运营 | 年度运维、云资源、维保、升级                                  |

## 9. 效益分析

- **安全效益**：由被动响应转为主动预警，缩短事件响应时间；
- **经济效益**：降低安保人力依赖，减少设备故障损失；
- **管理效益**：流程线上化、考核数据化；
- **社会效益**：提升业主安全感与满意度，支撑基层治理。

## 10. 保障措施

组织保障（领导小组+项目组）、制度保障（管理办法+操作规程）、资金保障、人才保障、运维保障（SLA+应急预案）。





# 文档四：《数据库表结构设计》

## 1. 设计规范

- 引擎InnoDB，字符集utf8mb4，排序规则utf8mb4_general_ci；
- 主键`id` BIGINT雪花算法，不建外键，逻辑关联；
- 逻辑删除`del_flag`（0正常 1删除）；
- 公共字段：`create_by/create_time/update_by/update_time/del_flag/remark`；
- 多小区隔离：业务表带`community_id`；
- 命名：小写+下划线；索引`idx_字段`、唯一`uk_字段`；
- 高频查询表按`community_id+create_time`建联合索引；流水类表按月分区或归档。

## 4. 归档与扩展策略

- `sec_access_record`、`sec_vehicle_pass`、`iot_device_status_log`：按月分区，热数据3个月，冷数据归档至ES/对象存储；
- 设备高频遥测（温度、电压等）入TDengine，不入MySQL；
- 多小区规模扩大后按`community_id`做分库分表（ShardingSphere）预留；
- 人脸/身份证/手机号采用AES加密存储，展示脱敏，密钥由KMS管理。

## 4. 关键流程（MVP必通）

1. **业主入住**：导入房屋→业主认证→绑定房屋→下发人脸/门禁权限→小程序开门；
2. **访客到访**：业主邀约→生成二维码→访客扫码开门→记录+通知业主；
3. **告警闭环**：设备/AI告警→平台弹窗+推送→安保接单→现场处置→反馈→归档/转工单。

## 5. 非功能要求

- 开门响应≤1s；告警推送≤3s；
- 门禁断网本地可用；NVR本地录像不依赖平台；
- 敏感数据加密脱敏；操作留痕。

## 6. 明确不做（MVP Out）

- 自研AI算法训练平台、数字孪生、复杂缴费与支付分账、多租户SaaS计费、复杂工作流编排、3D大屏、电梯/消防全量接入（可预留接口）。

- 三条关键流程端到端跑通；
- 性能指标达标；安全扫描无高危漏洞；
- 试运行2周无P0/P1缺陷。
